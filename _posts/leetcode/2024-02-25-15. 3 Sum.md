# 문제
[https://leetcode.com/problems/3sum/](https://leetcode.com/problems/3sum/)   
  
**3개의 값을 더했을 때 0이 되는 각 idx를 List에 담아 반환하는 문제**  
단, 각 요소가 조합된 집합을 중복시켜 List에 담아서는 안 된다. 그리고 시간복잡도는 o(n^2) 이하로 풀어야만 한다.  

# 풀이
## 완전탐색  
idx를 활용한 연산 문제는 조합된 경우의 수를 잘 생각해서 문제를 풀어야 한다고 생각한다. 그리고 그 생각 과정을 통해 이해를 돕고, 효율적인 처리 방법을 도와주는 알고리즘 유형은 완.전.탐.색이라고 생각한다.  
해당 문제를 풀어보며 각 위치의 idx 관점에서 어떻게 중복 값을 제외시킬 수 있을까와 하나의 완성된 조합의 수가 이전의 조합의 수와 같은 조합된 수인지, 왜 그렇게 나올 수 밖에 없었는지에 대한 여러 가지 상황을 시뮬레이션해 보며 고찰하는 사고 능력을 훈련했다.  

**반복문**  
완전탐색 문제, 직관적으로 그냥 풀면 된다. 어려울 것 없다.  
반복문 3대장 i, j, k 얘네들을 각 위치에 지정시켜 차례대로 조합을 만들어 요구 값인 0을 만족시키면 List에 집어넣으면 된다. 그러나, 해당 문제는 시간복잡도 o(n^2) 이하로 처리해야 한다. 그렇기 때문에 완전탐색 최적화를 시켜도 정답 처리를 해 주지 않는다. 하지만 과정에서 분명히 얻는 이득을 생각한다면 시도해 볼만하다.  

**최적화를 하기 위한 두 가지 처리**  
1. 오름차순 정렬  
입력 값 각 요소는 뒤죽박죽 섞여있어, 단방향시키기 어렵다.  
이를 n log n의 알고리즘 처리를 통해 통제할 수 있는 환경으로 만들어줘야 한다.  
2. i, j, k 각 위치에서 중복 처리  
3대장 i, j, k 각 입장에서 경우의 수를 도식화를 해 보면 수 많은 조합이 나오고, 다음 위치의 조합의 수를 시뮬레이션 할 수 있는 생각을 할 수 있게 된다. 각 위치의 숫자가 고정된 물리적 위치임과 동시에 조합의 고정된 숫자임을 알 수도 있다.  
예를 들어 1, 2, 3의 입력 값을 통해 i = 1, j = 2, k = 3이고 list {1, 2, 3}일 때 i는 j, k 위치가 변하더라도 고정되어 있기 때문에 첫 번째 자리 수 1이 같으면서 여러 가지 조합의 수가 여러 개인 것을 알 수 있다.   
즉, 이를 통해 중복된 경우의 수를 유추할 수 있다는 것이다.  
![image](https://github.com/user-attachments/assets/cd7ffafd-2f3f-4596-9dda-9fbaa8eaac63)  

**if (i > 0 && nums[i - 1] == nums[i])**  
위 조건문을 파악했다면, i가 1일 때 조합의 수가 i - 1가 1일 때 조합의 수는 반드시 겹친다.  
이걸 알 수 있게 된다. 그렇다는 것은 두 번째 자리 수인 j나 세 번째 자리 수 k도 마찬가지로 조합의 수는 반드시 겹친다는 것을 깨닫게 된다.   

## 투포인터
완전탐색 풀이를 통해 사고 확장을 했다면, 투 포인터도 그냥 푸는 것이 아니라 최적화를 넣어 풀 수 있다.  
투포인터 기법을 사용하지만, 세 개의 수를 조합해야 하므로 i를 반복문으로 돌리면서 두 개의 포인터를 계속 돌려야 한다.  
즉, 어떻게 보면 세 포인터라고 할 수 있다?? 따라서 시간복잡도는 o(n^2)이다.  
-> i가 돌면서 n만큼 투포인터가 돌아가므로 오름차순 정렬을 해야 한다.  
그냥 처리해도 되겠지만, 최적화를 위해 해야 한다.  

1. **idx i 입장에서 중복 조합의 수를 피하기 위해**  
-> input 값 1, 1, 0, 2이 있다면 i가 0번이었을 때 1, 0, 2와 i가 1번 이었을 때 1, 0, 2는 겹치게 된다.  
따라서 if (i > 0 && nums[i -1] == nums[i]) continue; 조건문을 넣어준다.  
이는 완전탐색을 통해 문제 접근을 해봤다면 응용이 가능하다.  
2. **left와 right 각 pointer 입장에서 같은 요소를 미리 피하기 위해**  
-> input 값 1, 0, 0, -1, -1이 있다고 가정

위와 같이 {1, 0, -1} 조합의 수가 한 번 더 나오기 때문에 중복 처리를 해줘야 한다.

# 알고리즘 특징
1. 완전탐색 처리 시 효율적인 동작 처리를 하기 위한 조건 방법  
2. 투 포인터 처리 시 완전탐색의 효율적 동작 조건문을 응용하여 최적화 하는 방법  

# 시간복잡도
* Bruteforce O(n^3)  
* TwoPointer O(n^2)  

# 코드  
```
// brute force
    public List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> answer = new ArrayList<>();
        final int numsLen = nums.length;

        Arrays.sort(nums);

        for(int i = 0; i < numsLen - 2; i++) {
            final int fN = nums[i];
            if (i > 0 && nums[i - 1] == fN) {
                continue;
            }

            for(int j = i + 1; j < numsLen - 1; j++) {
                final int sN = nums[j];
                if (j > i + 1 && nums[j - 1] == sN) {
                    continue;
                }

                for(int k = j + 1; k < numsLen; k++) {
                    final int tN = nums[k];
                    if (k > j + 1 && nums[k - 1] == tN) {
                        continue;
                    }

                    final int sum = fN + sN + tN;
                    if (sum == 0) {
                        answer.add(Arrays.asList(fN, sN, tN));
                    }
                }
            }
        }

        return answer;
    }
```

// twoPointer
    public List<List<Integer>> threeSum2(int[] nums) {
        List<List<Integer>> answer = new ArrayList<>();
        
        Arrays.sort(nums);
 
        for(int i = 0; i < nums.length; i++) {
            final int fn = nums[i];
            if (i > 0 && nums[i - 1] == fn) {
                 continue;
            }
 
            int s = i + 1;
            int e = nums.length - 1;
            while(s < e) {
                final int sum = fn + nums[s] + nums[e];
                if (sum < 0) {
                    ++s;
                } else if (sum > 0) {
                    --e;
                } else {
                    answer.add(Arrays.asList(fn, nums[s], nums[e]));
 
                     while(s < e && nums[s] == nums[s + 1]) {
                         ++s;
                     }
                     while(s < e && nums[e] == nums[e - 1]) {
                         --e;
                     }
 
                    ++s;
                    --e;
                }
            }
        }
 
        return answer;
     }
