## 도커 정의
- 컨테이너 기술 기반으로 애플리케이션과 그 실행 환경(라이브러리, 종속성)을 하나의 이미지로 패키징하여, 어떤 환경에서도 일관되게 실행할 수 있게 해 주는 오픈 소스 플랫폼

### 특징
- 컨테이너화
    - 애플리케이션을 컨테이너라는 격리된 환경에서 실행시켜, 다른 시스템에 영향을 주지 않는다.
- 가벼움
    - VM 머신과 비교했을 때, 상대적으로 APP 실행에 필요 데이터들만 사용해서 자원을 효율적으로 사용한다.
- 관리 및 배포
    - 원래의 이미지 위에 여러 레이어를 구성해서 확장할 수 있고, 하나의 컨테이너에서 구동되기 때문에 사실상 모든 환경에서 일관되게 유지 및 관리가 가능하고 배포가 쉬워진다.
- GO 언어
    - Docker는 Go 언어로 작성되어 있다.
    - Go는 경량화된 실행 파일을 만들 수 있어 여러 플랫폼에 손쉽게 배포할 수 있다는 장점이 있다.
- 네임스페이스 기능
    - 도커 컨테이너는 고유한 네임스페이스를 가지고, 호스트나 다른 컨테이너의 프로세스나 네트워크와 격리된 상태로 실행하므로, 여러 컨테이너가 같은 호스트에서 실행되더라도 서로 간섭하지 않는다.
    - 호스트 시스템의 커널을 공유하지만, 격리된 환경을 통해 더 적은 리소스로 여러 컨테이너들을 동시에 효율적으로 관리할 수 있다.

### 장점
- 단일 호스트의 OS 커널을 공유하기 때문에 경량성과 빠른 실행 속도를 가진다.
- OS 외에 애플리케이션 실행에 필요한 모든 데이터를 패키징하기 때문에 환경에 제약받지 않는다.
- 각 서비스를 컨테이너로 분리해서 독립적으로 관리할 수 있기 때문에 확장성을 가진다.
- 이미지 버전 별로 태그를 붙일 수 있어서, 버전 별로 관리가 가능하다.

### 단점
- 단일 호스트 OS 커널을 공유하므로, 보안에 취약할 수 있다.
- 지속적으로 저장해야될 서비스에서는 따로 볼륨이나 외부 스토리지를 설정 및 관리해야 한다.

## 도커 아키텍처
<img src="/assets/image/posts/summary of docker-1.png" alt="empty"
                    style="width: 100%; height: auto;">  

- 도커는 클라이언트-서버 아키텍처 구조를 가지며, 주요 구성 요소는 Docker Client와 Daemon이다.

### 클라이언트(Client)
- 도커와 상호작용하는 사용자 인터페이스
- 사용자의 명령을 받아서 이를 Daemon에게 전달하는 역할

### 데몬(Daemon)
- Docker 객체와 컨테이너를 관리하고, REST API를 통해 클라이언트와 통신

### 객체
- **이미지**: 실행할 수 있는 애플리케이션을 포함한 템플릿
- **컨테이너**: 이미지를 기반으로 실행되는 인스턴스
- **네트워크**: 컨테이너 간의 통신을 관리.
- **볼륨**: 컨테이너 데이터 저장소.
- **플러그인**: Docker의 기능을 확장할 수 있는 구성 요소.

<br>

## 컨테이너(Container)
- 독립적이고 격리된 환경에서 실행할 수 있도록 애플리케이션과 그 의존성을 하나의 패키지로 묶은 것
- 컨테이너는 이미지의 실행 가능한 인스턴스이다.

### 특징
- 경량화: 가상 머신보다 자원 소모가 적고 빠르게 실행
- 격리: 각 컨테이너는 독립적인 환경에서 실행되어 다른 컨테이너나 호스트 시스템과 간섭하지 않는다.
    - 네임스페이스(Namespaces)가 컨테이너 간의 격리를 제공하기 때문이다.
    - 컨트롤 그룹 (Cgroups)이 컨테이너가 사용하는 CPU, 메모리, 네트워크 등의 자원을 제한하고 모니터링할 수 있게 관리한다.
- 이식성: 한 환경에서 실행된 컨테이너는 다른 환경에서도 변경 없이 동일하게 실행된다.
- self-contained: 각 컨테이너는 실행에 필요한 모든 것을 포함하고 있어 호스트 머신에 설치된 의존성에 의존하지 않는다.

<br>

## 이미지
- 컨테이너 이미지는 컨테이너를 실행하는 데 필요한 파일, 바이너리, 라이브러리, 설정 등을 모두 포함한 표준화된 패키지
    - Docker 컨테이너를 생성하기 위한 읽기 전용 템플릿

### 특징
- 불변성: 한 번 이미지를 생성하면 수정할 수 없다. 변경 사항을 추가하려면 새로운 이미지를 만들거나 기존 이미지 위에 변경을 추가해야 한다.
- 계층(layer)구조: 이미지의 계층은 여러 읽기 전용 레이어로 이루어져 있다. 각 레이어는 변경 사항을 포함하고 있으며, 이전 레이어의 내용을 기반으로 추가적인 작업이 이루어있다.

### 이미지 레이어

- 도커 이미지는 파일 시스템을 여러 개의 읽기 전용 레이어로 나누어 구성한다. (파일 시스템의 변화)
- 이미지 레이어는 도커 이미지의 읽기 전용 계층으로, 각 명령어가 실행될 때마다 새로 생성한다.
- 각 레이어는 불변이므로, 한 번 생성된 후에는 수정되지 않는다.
- 도커는 이미지 캐시를 활용하여 변경되지 않은 레이어를 재사용하고, 이미지를 효율적으로 관리한다.
    - 디스크 공간을 절약하고, 이미지 빌드 시간을 단축
- docker history와 docker inspect 명령어를 사용하여 이미지를 구성하는 각 계층을 확인할 수 있다.
- 이러한 레이어들은 모두 결합되어 컨테이너가 실행되는 파일 시스템을 구성한다.

**예시**  
```
FROM ubuntu:20.04              # Layer 1: Base image
RUN apt-get update             # Layer 2: Update packages
RUN apt-get install -y python3 # Layer 3: Install Python3
COPY . /app                    # Layer 4: Copy application files
```

## 레지스트리(registry)
<img src="/assets/image/posts/summary of docker-4.png" alt="empty"
                    style="width: 70%; height: auto;">  

- 도커 이미지 파일을 저장, 관리, 배포, 공유하는 시스템(도커 이미지의 저장소 역할)
    - 공개 또는 비공개 설정이 가능
- Docker Hub는 공개 레지스트리이며, 글로벌 마켓플레이스이다.
    - 무료로 제공되며, 도커 이미지를 검색하고 다운로드할 수 있는 서비스

### 레포지토리
- 레포지토리는 레지스트리 내에서 관련된 컨테이너 이미지들을 모은 집합
    - 여러 개의 이미지를 프로젝트별로 정리한 폴더
- 특정한 이름을 가진 도커 이미지의 집합체
    - 하나의 저장소 내에는 여러 버전의 이미지가 태그(tag)로 구분

<br>

## Docker Compose
- 여러 개의 도커 컨테이너를 정의하고 관리할 수 있게 도와주는 도구
    - 여러 개의 서비스를 하나의 YAML 파일로 구성하고 실행할 수 있다.
    - 여러 컨테이너로 이루어진 복잡한 애플리케이션을 정의하고, 쉽게 실행할 수 있다.

### Dockerfile vs Compose 파일
- Dockerfile은 이미지를 만들기 위한 설정이고, Compose 파일은 여러 컨테이너를 어떻게 실행할지 정의하는 설정
