## 디스크 기반 데이터베이스
데이터를 디스크에 저장하는 방식의 데이터베이스를 **디스크 기반 데이터베이스**라고 한다. 디스크 기반 DB는 아직도 많은 곳에서 꾸준히 사용되고 있는 전통적이고, 일반적 방식이다. 

### 장점
1. **대용량 데이터 저장**
    1. 대용량 데이터를 지속적으로 저장할 수 있는 공간을 제공
    2. 기업의 트랜잭션 기록, 로그, 비즈니스 데이터를 안전하게 보관하는 데 유리
2. **영속성 보장**
    1. 데이터를 영구적으로 저장할 수 있다. 시스템이 종료되거나 크래시가 발생해도 데이터 손실 위험이 적음.
3. **트랜잭션 관리**
    1. 데이터 변경 작업 실패시, 이전 상태로 되돌릴 수 있는 트랜잭션 기능 제공
    2. 금융, 전자상거래 등에서 무결성(ACID) 보장
4. **데이터 백업 및 복원**
    1. 백업이 용이하고, 데이터 복구를 위한 방법들이 잘 갖춰져있다.

### 단점
- **속도 제한**
    - 데이터에 접근하는 속도(읽기/쓰기)가 느려서, 특히 대규모 데이터를 처리하거나 실시간 응답이 중요한 애플리케이션에서는 성능이 떨어진다.
- **디스크 I/O 병목 현상**
    - 디스크에 데이터를 쓰고 읽는 작업에서 I/O 작업이 병목을 일으킬 수 있다. 많은 양의 데이터를 자주 처리할 경우 성능 저하가 우려된다.
- **리소스 소모**
    - 디스크 기반 시스템은 디스크 용량, 디스크의 회전 속도, 메모리와 CPU를 많이 소모하는데, 이로 인해 시스템 자원에 부담을 줄 수 있다.
- **데이터 일관성(정합성) 문제**
    - 디스크 기반 시스템에서 여러 사용자가 동시에 접근할 경우, 데이터 일관성을 보장하기 위한 잠금(locking) 메커니즘이 복잡해질 수 있어, 이로 인해 성능 저하나 동시성 문제를 야기할 수 있다.

### 인 메모리 필요성
HW와 SW가 나날이 발전함에 따라 애플리케이션은 복잡성을 띄고 있고, 그리고 감당할 수 없는 엄청난 트래픽을 기존 디스크 방식으로는, 효율적인 운영이 어렵다. 이에, 데이터를 디스크가 아닌 RAM에서 관리하는 인메모리 데이터베이스 시스템이 등장하였다.

인메모리 데이터베이스는 데이터를 RAM에 저장하여 디스크 기반 데이터베이스의 한계를 극복하려고 등장한 시스템이다. 특히, 디스크가 아닌 RAM에서 읽기/쓰기를 처리함으로써, 실시간 분석 처리, 고속 트랜잭션 처리, 대규모 온라인 게임 실시간 상태 관리 등에서 최적의 효율을 발휘한다.  

## 인메모리 데이터베이스란?
인메모리 데이터베이스는 디스크가 아닌 메모리에 데이터를 저장 및 처리하는 DBMS이다. 

### 장점
1. **대규모 데이터 처리**
    1. 디스크와 비교해서 접근 속도가 수천 ~ 수만 배 빠르다.
2. **낮은 지연 시간**
    1. 실시간 처리가 필요한 SW에 적합
    2. 실시간 분석 처리, 트랜잭션, 대규모 온라인 게임의 실시간 상태 관리, 전자상거래
3. **복잡한 쿼리와 조인 연산 처리**
    1. 데이터 분석 및 보고서 처리에 효율적
    2. 빅데이터 분석과 머신러닝 모델 훈련

### 단점
1. **높은 가격과 낮은 용량**
    1. 메모리 용량과 비용을 고려하여, 데이터를 효율적으로 관리해야 한다. 
2. **데이터 비영속성**
    1. 휘발성 특성으로 인한 데이터 손실 및 소멸
    2. 정기적 백업 비용과 상황에 맞는 복구 전략이 필요

### 인메모리 데이터베이스 종류
인메모리 데이터베이스의 종류는 유형에 따라 다양하다. 그중에 일반적으로 알려진 **Redis와 Memcached**가 있다.
