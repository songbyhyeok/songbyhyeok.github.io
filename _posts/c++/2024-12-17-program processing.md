# 개요
![image](https://github.com/user-attachments/assets/7a91ffb3-2ba4-4221-9732-fd73e976beb6)  
프로그램이란 실행될 수 있는 프로그래밍된 결과물을 말한다. c++은 프로그램을 만들기까지 여러 과정을 거치게 되는데 크게 4단계를 거치게 된다. 소스 작성 -> 선행처리 -> 컴파일 -> 링크 단계가 있다. 이 모든 일련의 과정을 통틀어 **빌드**  라고 하며, 그리고 파일을 실행하여 main() 함수가 동작하면서 프로그램이 작동되는 것을 **프로그램 실행** 이라고 표현한다.  

그러면 구체적으로 어떻게 하나의 프로그램이 생성이 되는지 알아보자.

# 소스 프로그램
우리가 익히 아는 **코딩** 행위를 하여 c++ 문법에 맞게 명령어 집합을 적어낸 파일을 말한다. 소스 프로그램은 소스 파일과 헤더 파일로 구성된다.  

## 통합개발환경 IDE
* 프로그램 개발에 사용되는 여러 가지 도구 패키지
* 소스 코드 작성에 쓰이는 텍스트 에디터 제공
* 오류 발견 및 수정 도구 디버깅 제공
* 개발 과정 중 오타 및 자동 코드 생성등 생산성 효율을 높임

## 소스 파일
* 명령어 집합인 하나의 프로그램이 작성된 .cpp 확장자를 사용하는 소스 정의 구성 파일
* 코드 정의를 담는 것이 일반적이나 간단한 수준은 선언도 포함시켜 프로그램 생성 가능
* 팀 프로젝트 같은 협업 중심의 복잡성을 요구하는 프로그램은 소스 파일만으로는 유지보수 및 확장 관리가 불가능

## 헤더 파일
* 소스 코드에 선언 부분을 구조화시킨 .h 확장자를 사용하는 파일
* 여러 소스 파일에 코드 중복성을 방지 및 필요에 따라 공통 사용 목적
* 선행지시기 #include 키워드를 사용해서 헤더 내용을 소스 파일에 삽입
* 외부 라이브러리나 임의 헤더를 사용하여 유지보수, 확장, 코드 간소화가 가능

### 라이브러리 ?
-> 개발에 필요한 특정 기능들을 외부에서 정의된 도구 또는 명령어 집합 즉, 모듈화 프로그램  
-> 값, 함수, 클래스 등 모아 놓은 것  

## 선언과 정의?
컴파일러에게 사용할 형식 및 명칭을 알려주는 것을 **선언**  이라고 하고, 그리고 선언된 형식에 내용을 입력하는 것을 **정의** 라고 한다.  

### 차이점 
* **extern int j;**  
-> 외부 파일에 존재하는 코드를 사용할 수 있게 컴파일러에게 존재 여부를 알리는 것, 저장 공간을 할당한 것이 아니기 때문에 중복 재선언이 가능

* **int i;**   
-> i라는 변수명은 int형 타입 크기를 가지고 메모리 특정 저장공간에 할당하라고 컴파일러에게 선언 및 정의를 명령하는 것을 정의라고 한다. 저장됐기 때문에 중복 정의는 불가능.  

### extern?
외부 파일에 존재하는 외부변수 및 함수를 가져다 사용하기 위한 전역적 목적 키워드

# 선행처리

컴파일 이전에 선행처리기 지시어에게 소스 파일 및 헤더 파일을 결합시켜 단일 소스 프로그램으로 가공하라고 명령하는 것

## 번역 단위
하나의 소스 파일과 하나 이상의 헤더 파일들을 단일화시킨 것  
-> 프로그램은 한 개 이상의 번역 단위로 모듈화

## 선행처리기 지시어
![image](https://github.com/user-attachments/assets/1feea60f-f6ea-442e-8f75-d694fd712c84)  
키워드 사용 시 '#'으로 시작되며, 한 행에 한 문장씩 작성된다.  
### 키워드 종류
* **#include**  
-> 소스 파일에 결합  
-> 표준과 임의 경로 두 개로 분류
-> "a.h" a.h 라는 파일을 "" 안에 절대 or 상대 경로 지정  
-> <'iostream'> 표준 include 경로에 존재하는 파일  
* **#define, #undef**  
-> 매크로 선언 및 해제  
* **#if, #ifdef, #ifndef**  
-> 조건부 컴파일 등 제공

# 컴파일, 컴파일러
번역 단위 파일들을 컴퓨터가 이해할 수 있는 어셈블리어로 번역시키는 과정, 그 행위자 프로그램을 컴파일러

## 목적 코드, 목적 파일
컴파일 이후 만들어지는 것을 번역된 코드를 목적 코드, 그리고 저장되는 파일을 목적 파일  
* 하나의 컴파일된 번역 단위에는 하나의 목적 파일이 생성된다.
* .obj 확장자를 사용
* A.cpp, iostream, a.h 구성된 하나의 번역 단위가 컴파일되어 A.obj가 생성

# 링크, 링커
목적 파일과 라이브러리들을 구성시켜 실행파일로 만들어주는 과정을 링크, 행위자인 도구를 링커라고 한다.

# 결론
C++의 소스 작성부터 실행까지의 과정을 학습했다.  
C++ 실행 과정을 학습하는 것은 프로그램의 동작 원리를 깊이 이해하고, 성능 최적화 및 디버깅 능력을 향상시키는 데 많은 도움이 된다. 구체적으로 메모리 관리, 성능 최적화, 디버깅, 하드웨어 자원 제어, 쓰레딩, 이식 및 플랫폼화 등등 다양한 기술들을 활용함에 있어 중요한 시초를 배웠다고 할 수 있다.
