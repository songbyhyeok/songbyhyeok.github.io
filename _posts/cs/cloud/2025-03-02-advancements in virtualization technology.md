# 소개
가상화 기술은 기업의 IT 인프라를 효율적으로 운영하고, 비용을 절감하며, 확장성과 유연성을 제공한다. 
또한, 시스템 관리와 보안 측면에서도 중요한 역할을 하며, 클라우드 컴퓨팅과 밀접하게 연관되어 있다.  

클라우드는 기업이 빠르게 변화하는 환경에 대응하고 경쟁력을 유지할 수 있도록 돕는다. 
가상화 기술을 기반으로 자원을 효율적으로 활용하고 관리할 수 있는 클라우드는 기업에게 큰 이점을 제공한다. 
이러한 이유로 가상화 기술은 학습하고 익혀야 할 중요한 기술이다.

## 초기 IT 인프라
초기 IT 인프라는 물리적 서버를 사용해 각 서버마다 하나의 애플리케이션만 실행하는 방식이었다.  

단일 구동 방식은 단순하고 사용하기 쉬웠지만, 많은 문제점들을 가지고 있었다.  

### 물리적 서버 자원의 비효율적 사용
각 서버는 운영 체제와 애플리케이션을 실행하기 위해 많은 자원을 소비했으며, 서버의 자원 활용도가 매우 낮았다. 
왜냐하면, 여러 서버를 운영하면서 각 서버에 운영 체제와 애플리케이션을 독립적으로 배치해야 했기 때문에 리소스 낭비가 심하고, 서버를 효율적으로 활용하지 못했기 때문이다.  

### 서버 격리와 보안 문제
각 서버가 물리적으로 독립적인 환경에서 운영되었지만, 서버 간의 격리가 충분하지 않아서 보안 취약점이나 시스템 충돌로 인한 문제 발생 시 전체 시스템에 영향을 미칠 수 있었다. 
이를테면, 서버 간의 격리가 제대로 이루어지지 않아, 하나의 애플리케이션에서 발생한 문제나 보안 침해가 다른 시스템에도 영향을 미치는 경우가 있었다.  

그래서 각 서버에 대해 독립적인 보안 환경을 관리하는 것이 필요했다.  

### 서버 운영과 관리의 복잡성
물리적 서버에서 다양한 운영 체제와 애플리케이션을 실행하려면 각 서버에 대해 개별적인 관리가 필요했다. 
왜냐하면 서버의 설정, 배포, 유지보수가 복잡하고, 수많은 서버를 관리하는 데 드는 인력과 시간이 많이 소모되었기 때문이다.  

이러한 여러 문제점들을 해결하기 위해 등장한 것이 바로 가상화 기술이다.  
<br>

## 가상화 기술
가상화 기술은 물리적 서버 자원을 가상화하여 여러 개의 가상 머신(VM)을 하나의 물리적 서버에서 실행할 수 있게 해주며, 각 가상 머신은 독립적인 운영 체제와 애플리케이션을 실행할 수 있다.  

가상화는 단일 구동 방식의 본질적 문제들을 해결해 주었다.  

### 가상화 장점 
1. **자원 효율성**  
하나의 서버에서 여러 가상 머신을 실행하여 하드웨어 자원의 활용도를 극대화  

2. **서버 격리**  
 가상 머신은 독립적인 환경에서 실행되기 때문에 다른 가상 머신에 영향을 주지 않으며, 보안과 안정성을 강화  

3. **운영 효율성**  
여러 서버를 하나의 물리적 서버에서 관리할 수 있으며, 가상 머신을 통해 관리가 용이  

4. **유연, 확장성**  
필요에 따라 가상 머신을 추가하거나 제거  
<br>

가상화는 여러 개의 가상 머신을 실행할 수 있게 해줬지만, 새로운 구조적 문제를 떠안게 되었다.

### 가상화 문제점
1. **가상화 오버헤드**  
각 가상 머신(VM)이 독립적인 운영 체제를 실행해야 하는 의존적 문제로 인한 오버헤드  

2. **앱 배포 복잡성**  
애플리케이션을 배포할 때, 운영 체제부터 설정하고 애플리케이션을 설치해야 하는 복잡한 과정이 필요  

3. **확장성과 유연성 제한**  
가상화는 여러 개의 가상 머신을 실행하여 수평 확장을 지원하지만, 확장성을 위한 시간과 리소스가 필요  

4. **개발 및 운영 환경에서의 일관성**  
가상 머신이 독립적인 운영 체제를 실행하므로, 각 가상 머신 간의 환경 차이가 발생  

5. **DevOps 및 CI/CD 파이프라인 지원**  
가상화는 DevOps 환경에서 어느 정도 활용할 수 있지만, 많은 자원과 시간이 소요되기 때문에 자동화된 배포와 빠른 피드백을 구현의 한계  

6. **마이크로서비스 아키텍처 지원**  
가상화는 여러 가상 머신을 실행하지만, 각 가상 머신은 비교적 무겁고, 빠른 확장이 어려워 마이크로서비스 환경에 비적합  

이러한 문제점들은 현대적인 개발 및 운영 환경에서 요구되는 민첩성, 확장성, 효율성을 충족시킬 수 없다. 때문에, 컨테이너 기술을 사용해야 하는 이유이기도 하다.  
<br>

## 컨테이너 기술
컨테이너 기술은 애플리케이션과 그 실행 환경을 독립적으로 격리하여 실행할 수 있게 해주는 기술이다.  

가상머신 기술과 유사한 개념이지만, 구조적인 관점에서 차이가 존재한다. 

가상 머신은 하드웨어 자원을 가상화하여, 각각의 가상 머신이 독립적인 운영 체제와 애플리케이션을 실행하는 구조이지만, 컨테이너는 운영 체제의 커널을 공유하고, 애플리케이션과 그 환경만을 격리하여 실행한다. 때문에 컨테이너는 독립적인 실행 환경을 제공하지만, 운영 체제는 공유되므로 자원 소모가 훨씬 적고 가볍고 빠르다.  

### 컨테이너 특징
1. **경량화된 실행 환경**  
컨테이너는 애플리케이션과 필요한 라이브러리, 설정 파일을 포함한 경량화된 실행 환경을 제공한다. 하나의 운영 체제 커널 위에서 여러 컨테이너가 실행되기 때문에 자원 소모가 적고, 빠르게 실행할 수 있다.  

2. **애플리케이션 격리**  
컨테이너는 독립된 환경에서 애플리케이션을 실행하기 때문에, 서로 다른 컨테이너는 격리되어 실행된다. 예를 들어, 한 컨테이너에서 발생한 오류가 다른 컨테이너에 영향을 미치지 않는다.  

3. **이식성**  
환경의 일관성을 보장한다. 애플리케이션과 그 실행 환경을 함께 패키징하므로, 개발, 테스트, 운영 환경에서 동일한 방식으로 실행할 수 있다.  

4. **배포와 관리의 용이성**  
애플리케이션과 그 의존성을 하나의 패키지로 묶을 수 있다. 예를 들어, Docker와 같은 도구를 사용하면 여러 환경에서 동일한 컨테이너 이미지를 실행할 수 있다.
