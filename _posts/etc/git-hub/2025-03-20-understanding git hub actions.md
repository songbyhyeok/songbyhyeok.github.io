# 깃허브 액션이란
GitHub에서 제공하는 CI/CD 플랫폼이다. 개발자는 코드를 푸시할 때마다 자동으로 빌드, 테스트, 배포 등의 작업을 수행할 수 있도록 설정할 수 있다. 또한, GitHub Actions는 GitHub 저장소와 밀접하게 통합되어 있어, 저장소에서 직접 자동화된 워크플로우를 만들고 관리할 수 있다.

## 구성요소
### 이벤트(Event)
워크플로를 실행시킬 수 있는 발동 장치이다.  

작업 시작 신호라고 표현할 수 있다.
### 워크플로우(Workflow)
워크플로우는 하나 이상의 작업(Job)을 포함하며, GitHub 저장소의 특정 이벤트에 의해 트리거된다.  

워크플로우는 일종의 전체 작업 계획서와 같다. 구체적으로 어떤 일이 언제, 어떻게 실행될지를 구체적으로 문서화한 것이다.
### 작업(Job)
워크플로우 안에서 실제로 이루어지는 세부적인 단계(Step)의 집합이다. 각 작업은 개별적이면서 종속적이다. 따라서 하나의 작업이 다른 작업에 종속될 경우에 차례대로 실행될 수 있게 할 수 있고, 그리고 데이터를 공유가 가능하다. 만약, 종속적이 없다면 병렬로 실행된다. 구문은 셸 스크립트로 되어 있다.  

작업은 세부 작업 리스트와 같다.
### 스텝(Step) 
스텝은 하나의 작업을 이루는 개별적인 단계이다.  

스텝은 작업 과정이다. 이는 공장에서 일하는 사람이 수행하는 하나 하나의 세부 행동에 해당된다. 
### 러너(Runner)
실행기는 트리거될 때 워크플로를 실행하는 가상화 서버를 말한다. 각 러너는 한 번에 하나의 작업을 실행할 수 있다. 실행기는 여러 운영체제를 제공한다. 우분투, 윈도우, 맥 등  

실행기는 실제 작업을 수행하는 사람이다. 

### 정리
구성요소를 정리하자면 다음과 같은 순서로 단계가 진행되는 것을 알 수 있다.  

이벤트(시작 신호) -> 워크플로우(작업 계획서) -> 작업(작업 단계) -> 단계(작업 과정) -> 러너(작업 실행 환경)
