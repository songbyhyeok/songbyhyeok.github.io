# 개요
예전 C, C++을 배우면서 문법 중 가장 기억에 남는 것이 있다면 바로 const이다. 그땐, 해당 키워드를 사용하지 않더라도 잘만 동작됐기 때문에 굳이 필요성은 못 느꼈지만 단순히 봤을 때 '멋'이 있어 보인다는 이유 하나만으로 습관화하려고 노력했던 거 같다. 지금은 어떤지는 모르겠지만 배울 당시에 const에 대해 설명하는 사람들도 하나같이 사용할 수 있으면 도배하라고 귀에 못이 박히도록 들었으니 뭐 말 다 한 거 같다.  

이번 글에서는 const와 constepxr를 중점적으로 다룰 예정이지만 연관된 다른 개념들도 포함하려고 한다.

## 학습 전 알아야 할 상식 용어
### 컴파일?
'컴파일러' 도구를 사용해서 고급 언어를 저급 언어인 기계어(어셈블리어)로 변환해 주는 것  
IDE를 사용해서 개발한 원시 코드(소스 코드)를 목적 코드로 옮겨 하드웨어가 처리하기에 좋은 환경을 제공해주는 역할  

### 런타임?
목적코드 이후 단일된 프로그램이 실행되어 프로세스가 동작되는 시점을 말한다.  

**두 개념의 에러적 차이**  
컴파일 에러는 대부분 IDE 환경에서 문법적 이슈로 컴파일 검증 과정을 거치지 않더라도 개발자가 미리 에러를
알고 처리할 수 있지만, 런타임 에러는 실행 이후 과정이기 때문에 예상치 못한 이슈나 버그가 발생하게 된다.
예를 들어 0을 나누거나, Null을 참조하거나, 오버플로우 현상, 메모리 누수 등등이 있다.  

## 상수
### 리터럴?
상수의 대표적 개념으로 기본 자료형의 값을 직접 표현한 것, 메모리에 저장된 불변적 데이터를 말한다.  
-> ex int a = 55(리터럴);  

### 매크로 상수
키워드 #define을 선행처리기 지시어를 사용하여 매크로 상수로 만들 수 있다. 하지만, C계열 방식이라 C++에서는 const를 사용하는 것이 일반적이다.  

### const?
자료형 앞에 const 한정어 키워드를 사용함으로써 변수를 런타임 상수로 만들 수 있다.  

### constexpr?
자료형 앞에 constexpr 한정어 키워드를 사용해서 컴파일 상수로 만든다. 그리고 사용 시 장점은 다음과 같다.
* **코드 가독성**  
코드의 의도를 명확하게 전달할 수 있다.
* **컴파일 오류**  
컴파일 때 상수로 지정시켜야 할 값을 런타임 때 변경시키는 불상사를 막을 수 있다.
* **런타임 비용 절감**  
컴파일 때 상수 값을 미리 결정시켜, 추후 런타임 연산 처리 비용이 절감

**자료형 한정어(type qualifier)?**  
자료형에 대해 특성을 부여하는 키워드  

**코드 이해**  

```
    int i;
	cin >> i;
	const int a = 20;
	const int b = a;
	const int c = i;
	constexpr int d = a + b;	// 리터럴 값을 저장한 a는 컴파일 때 처리가 가능.
	constexpr int e = a + 100;	// 변수 a와 리터럴 100은 둘 다 컴파일 때 처리가 가능.
	constexpr int f = c;		// 입력값 변수 i를 저장하는 변수 c는 런타임 때 처리가 가능.
	constexpr int g = i + 20;	// 입력값 변수 i는 런타임 때 실행되므로 컴파일 때 불가능.
```

## 사용해야만 하는, 습관화시켜야 하는 이유
코드 작성을 컴파일 및 런타임 때 변수나 함수를 상수로 지정함으로써 코드에 의미를 부각시켜 의사소통이 가능케 하고, 사전에 수정해서는 안되는 값을 바꾸어 불상사 사고를 미연에 방지하여 안정성을 높여줄 수 있다. 따라서 키워드를 사용할 수 있다면 적절하게 반드시 사용해주는 것이 옳다.
